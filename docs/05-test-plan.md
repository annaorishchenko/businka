## Цели тестирования

1. Убедиться, что все шесть страниц открываются без ошибок.
2. Проверить корректность всех навигационных переходов.
3. Подтвердить работоспособность кликабельных контактов (телефон, email, мессенджеры).
4. Удостовериться в адаптивности на четырёх ключевых разрешениях.
5. Проверить корректное поведение страницы 404.
6. Убедиться, что дисклеймер о Meta отображается рядом со ссылкой на Instagram.

## Виды тестирования

| Вид | Покрытие | Способ |
|---|---|---|
| Функциональное (ручное) | Навигация, контакты, 404 | По чек-листу тест-кейсов |
| Адаптивное (ручное) | 1920 / 1366 / 800 / 375 | Chrome DevTools, реальные устройства |
| Юнит-тесты | Компоненты `shared/ui`, бургер-меню | Vitest + Testing Library |
| Smoke-тесты страниц | Рендер без ошибок | Vitest |
| Кросс-браузерное | Chrome, Safari, Firefox, Edge | Ручная проверка ключевых сценариев |
| Производительность | LCP, CLS, TBT | Lighthouse |

## Критерии прохождения

Тест считается **пройденным**, если фактический результат совпадает с ожидаемым на всех заявленных разрешениях. При несовпадении заводится баг с приоритетом:

| Приоритет | Описание |
|---|---|
| Critical | Сайт не открывается или падает |
| High | Ключевая функция (меню, контакты) не работает |
| Medium | Адаптивный баг, который ухудшает восприятие |
| Low | Косметика, мелкие отступы |

## Регрессионный сценарий

Перед каждым релизом прогоняется сокращённый набор:

1. TC-001 — главная открывается.
2. TC-002, TC-003, TC-004, TC-005 — все пункты меню работают.
3. TC-008, TC-009, TC-010, TC-011 — контакты кликаются, дисклеймер Meta на месте.
4. TC-012 — 404 работает корректно.
5. TC-017 — мобильная версия не сломана.
6. TC-023 — перезагрузка не выдаёт «Cannot GET /catalog».

Если все шесть пунктов пройдены — релиз допускается.

## Отчётность

После прогона тест-плана QA заполняет колонки **Полученный результат**, **Скрин** (ссылка на изображение в системе), **Статус** (Passed / Failed / Blocked) и **Примечания**.

Дефекты заводятся в трекере (например, GitHub Issues или Trello) со следующими полями:

- Заголовок: краткое описание бага.
- Ссылка на тест-кейс (TC-XXX).
- Шаги воспроизведения.
- Ожидаемый и фактический результат.
- Приоритет.
- Скриншот / видео.
- Браузер и разрешение.

Финальный отчёт о тестировании прикладывается к релизу и хранится в `docs/test-reports/YYYY-MM-DD.md`.
